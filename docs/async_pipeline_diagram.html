AsyncVLA — Asynchronous Execution Pipeline

AsyncVLA decouples the heavy VLM backbone (low-frequency) from a lightweight Edge Adapter (high-frequency). The VLM produces compact action-token features offline, while the Edge Adapter fuses them with real-time camera observations to generate action trajectories at the robot's control rate.

Deployment Topology — Process & Thread Model

In real robot deployment, AsyncVLA is split across two physical machines communicating via ROS1 topics. The VLM backbone runs on a remote GPU workstation as a single-threaded Python process; the Edge Adapter runs on the robot's onboard controller as a separate process. The "async" in AsyncVLA refers to this architectural decoupling — not Python-level async/threading. In the codebase's single-machine inference mode (run_asyncvla.py), both run sequentially in one thread.

Remote Workstation (H100/H200 GPU)

Python Process — Main Thread (single-threaded)
Launched via python inference/run_asyncvla.py. Runs the full VLM forward pass sequentially: Vision Backbone → Projector → LLM → Action Token Extraction → Proj_Actiontokens. No threading or multiprocessing used. GPU operations dispatched from main thread via PyTorch CUDA calls.
CUDA Stream (implicit)
PyTorch default CUDA stream handles GPU kernel dispatch. All ops (torch.no_grad() + torch.autocast("cuda", dtype=bfloat16)) execute on cuda:0. No explicit multi-stream parallelism.
ROS1 Publisher (in deployment)
Publishes projected_actions [B, 8, 1024] features to a ROS topic. The Edge Adapter on the robot subscribes to this topic asynchronously. (Not implemented in the open-source codebase; see paper appendix.)
ROS1 TOPIC

Robot Edge Controller

Python Process — Main Thread (single-threaded)
Runs the Edge Adapter loop at 3 Hz (tick_rate). Each tick: read camera → run shead(img_cur, img_past, projected_actions) → delta_to_pose() → PD controller → publish (v, ω) commands. Uses the most recently cached VLA features from the ROS subscriber.
ROS1 Subscriber (callback)
ROS subscriber callback receives projected_actions from the remote workstation. Updates cached features in memory — the only point of inter-process data sharing. ROS internally uses a spinner thread to handle callbacks.
Robot Hardware Interface
Sends velocity commands (v, ω) to robot actuators. Reads camera frames and GPS/compass data for the next cycle.
Single-Machine Mode (run_asyncvla.py)
In the open-source codebase, both VLM and Edge Adapter run sequentially in one process, one thread on a single GPU. The inference loop calls vla() then shead() back-to-back. No ROS, no threading, no multiprocessing. This is a simplified offline evaluation mode. The async split across two machines uses ROS1 and is described in the paper appendix.

Training — Multi-GPU Process Model (DDP)

Training uses torchrun to spawn one process per GPU via PyTorch DistributedDataParallel (DDP). Each process runs an identical copy of the model on its assigned GPU. Gradients are synchronized automatically across processes during backward pass. Data is split across ranks via DistributedSampler.

Per-GPU Process (torchrun)

Launched via torchrun --nproc-per-node 5. Each GPU runs a full Python process. Training loop: forward pass → loss computation → loss.backward() → optimizer.step(). Gradient accumulation over 2 steps. Uses torch.autocast("cuda", dtype=bfloat16) for mixed precision.

DataLoader Workers (8 per process)

Each process spawns 8 worker subprocesses (num_workers=8, persistent_workers=True) for data prefetching. Workers load images from disk, apply transforms, tokenize text, and fill a prefetch queue. The main thread consumes batches from this queue. Total: 5 GPUs × 8 workers = 40 data-loading subprocesses.

Synchronization Points

dist.barrier() called at: checkpoint directory creation, model weight saving, LoRA weight merging, and model file syncing. DistributedSampler ensures each GPU processes different data. WeightedDistributedSampler balances dataset sampling weights.

Module Details

Vision Backbone

Fused dual-encoder: SigLIP ViT (semantic) + DINOv2 ViT (spatial). Each image → 256 patches. Two images (current + goal) → 512 total patches. Features concatenated along hidden dimension before projection.

Multimodal Projector

3-layer MLP with GELU: vision_dim → 4×vision_dim → llm_dim → llm_dim. Maps fused vision patch features into the LLM embedding space (4096-d).

Proprio Projector

2-layer MLP with GELU: 4 → 4096 → 4096. Encodes goal pose [x, y, cosθ, sinθ] as a single LLM-space token, appended after vision patches.

LLM Backbone

Llama-2 7B with LoRA (rank 32–128). Input: [BOS, vision_patches(512), proprio(1), text_tokens, action_tokens(32)]. Action token embeddings zeroed; positions filled by the causal transformer. Last-layer hidden states extracted at action positions.

Action Token Projector

Proj_Actiontokens: MLPResNet (2 blocks) with modality ID concatenation. Input: reshaped action hidden states [B, 8, 4096×4]. Output: compact action features [B, 8, 1024] for the Edge Adapter.

Edge Adapter

Lightweight module (~5M params). Two EfficientNet-B0 encoders: obs_encoder (3ch → 512-d) and cat_encoder (6ch → 512-d). Token sequence [vla_feat(8) | obs(1) | cat(1)] → 2-layer Transformer decoder → MLP → delta actions [B, 8, 4].

Delta-to-Pose

Integrates local delta predictions [dx, dy, cosΔθ, sinΔθ] into a global trajectory. Uses differentiable rotation transforms to accumulate pose: x += cos(θ)dx - sin(θ)dy.

9 Modality Modes

AsyncVLA supports 9 goal-conditioning modes via modality_id: satellite-only, pose+satellite, satellite+image, all, pose-only, pose+image, image-only, language-only, language+pose. The modality ID is injected into Action Token Projector via concatenation.
